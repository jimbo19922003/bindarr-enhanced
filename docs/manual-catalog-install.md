# Manual staged catalogue installation

Stage the extracted metadata artifact from a trusted repository build on the test server, outside publicly served directories, and configure POKEMON_CATALOG_BUNDLE_DIR to its root. It must contain manifest.json, LICENSE and the selected language exports. Restart the test process if needed to load changed environment configuration. The current workflow produces English by default. This commit does not download or stage an artifact for any instance.

In Admin, enter the full upstream commit from that artifact, choose the installed/selected language (English initially), and request a verified preview. The server verifies checksums, source identity, language, license and normalization through the existing bundle loader, then retains a private copy for ten minutes. Checksums detect corruption; they are not a signature establishing the publisher. Only use trusted artifacts.

Confirm the preview to install that exact source snapshot. This explicitly replaces the active metadata snapshot for the chosen language; choosing an older source is not automatically prohibited. Existing collection IDs and price fields are preserved by the metadata importer. No image bytes are downloaded and local API mode is not enabled by installation. The background job can be checked with Refresh import status; a lost HTTP connection does not cancel the import. Preview tickets and job status are process-local, so a restart requires a new preview and database status should be checked.

Only the server-configured bundle directory is used; requests cannot supply a filesystem path, URL or arbitrary command. Installation requires an administrator session and explicit confirmation. A verified preview does not write the database. Failed imports use the existing transaction rollback behavior. Multi-process scheduling, automatic secure delivery, full scanner refresh, external fallback adapters and final migration/housekeeping review remain unfinished.
