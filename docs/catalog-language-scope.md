# English and Japanese catalog builds

The default manual and scheduled compilation, packaging and scratch import languages are en and ja. Additional supported languages must be selected explicitly with the workflow language input. Independently of these ready-made bundles, Admin → Catalog can sync every physical TCGdex set for a selected language into the active local metadata snapshot, or sync one selected set. Each set is merged transactionally and separately; a failed bulk run preserves sets already completed so the operation can be safely retried. This does not install a ready-made snapshot or automatically build a scanner index.

The temporary compiler copy has its actual LANGS loop scoped to the requested languages. Git last-edit indexing runs only over the source folders those languages use: data for English/European languages and data-asia for the Asian languages. Empty newline entries are removed before Git-history lookups; genuine lookup failures still report the filename. The previously observed two blank filename warnings were caused by those empty entries, not SQLite imports.

English-only builds do not apply the BW3b correction or process Asian source history. Explicit Asian-language builds retain that reviewed correction. The validation report records compiler scope, selected source folders and transformation hashes alongside source corrections.

This is a candidate-bundle CI build, not a new full compilation task on server startup. The sync controller already defaults to en. Runtime bundle delivery and complete local API cutover remain separate from per-set metadata sync. The repository checkout remains complete and per-file Git-history work remains for the selected source tree; runtime reductions must be measured, not assumed. Existing stored languages and user data are not removed.
